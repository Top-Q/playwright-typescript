## Preconditions

- Work Package A has a child Work Package C that is not Closed ^a-has-open-child
- Work Package B has no children

## Steps

1. In the Work Package list, select A and B
2. Open the context menu and choose Delete
3. Try to confirm the deletion without ticking the acknowledgement
4. Tick "I acknowledge that ALL descendants of the listed work packages will be recursively removed." and confirm

## Expected result

The confirmation dialog lists A and B, shows that A has a child, and warns "All child work packages and their descendants will also be recursively deleted." Delete stays disabled until the acknowledgement is ticked. Once confirmed, A, its child C and B are all deleted; nothing is kept back because a child is open.

## Notes

Exercises, inside a bulk operation, the protection [[FR-WP-013]] asks for: deleting a Work Package with children requires an explicit cascade confirmation.

Rewritten 2026-09-23 against OpenProject 16, together with [[BR-WP-04]], which carries the evidence. The previous version expected the item with open children to be kept back while the rest were deleted; OpenProject asks one acknowledgement for the whole selection and then deletes every selected Work Package with all of its descendants, permanently.
