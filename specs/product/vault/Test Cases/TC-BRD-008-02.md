## Preconditions

- A user whose Role in the Project grants 'Edit work packages' but neither 'Manage boards' nor 'Manage public views'. No default Role does, so this needs a custom Role.
- A Basic Board with two lists, a card in the first

## Steps

1. Drag that card to a different list

## Expected result

The move succeeds despite the user lacking Board management permission.

## Automated by

![[Automated by.base]]

## Evidence

Checked 2026-10-08 against OpenProject 16 (Rails source `stable/16`, v16.6.10), source only:

- A card can be dragged when its list's Query offers `updateOrderedWorkPackages`
  (`frontend/src/app/features/boards/board/board-list/board-list.component.ts:253,353`). That link
  is given to a user who may manage the public Query **or** may edit Work Packages in the Project
  (`app/policies/query_policy.rb:54-60,90-92`, `lib/api/v3/queries/query_representer.rb:130-137`).
- The default Member Role has 'Manage boards' and Reader cannot edit Work Packages, so no default
  Role isolates the case (`modules/boards/app/seeders/common.yml:34-41`).

## Notes

Corrected 2026-10-08: the actor was Team Member, whose Role holds 'manage boards' — see
[[Create-Delete Board]] — so it never exercised the case. Being the Assignee does not matter: the
check is on the Project-wide edit permission.
