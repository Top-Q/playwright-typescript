# The POM catalog

A committed, greppable index of every page object and its methods, generated from `src/po/`. It
exists so that agents and humans discover what already exists before writing a new page object —
avoiding duplicate methods and reinvented locators. CLAUDE.md rule 25 makes searching it
mandatory before a new method is written.

It lives in `pom-catalog/<app>/` and is generated by `scripts/build-pom-catalog.ts` — **repo tooling,
not a skill asset**, because the `gen-test` pipeline, this skill, and any hand-written test all
consume it. A skill has to stay removable; the catalog does not.

## Reading it

| File            | Holds                                                      |
| --------------- | ---------------------------------------------------------- |
| `index.json`    | Class-level overview: names, `@aliases`, module, file path |
| `<module>.json` | The methods for one module — signatures and metadata       |

**Start with `index.json`** to find the right class by name or by `@aliases`, then open only the
relevant `<module>.json`. The index deliberately carries no method-level data so it stays small as
the project grows — reading every module file to answer one question defeats the point.

Search by **intent**, not just by exact name. `@aliases` is what makes `inviteUser` find
`addMember`; grepping for the literal method name you have in mind is how a duplicate gets written.

The catalog is a discovery aid, **not** a substitute for reading the page-object source when you are
about to extend a class. It lists what exists and what it promises; the source is what tells you how
it behaves.

## Commands

| Command                  | Does                                                                                         |
| ------------------------ | -------------------------------------------------------------------------------------------- |
| `npm run catalog`        | Regenerate from `src/po/`. Run after adding or changing any page-object method.              |
| `npm run catalog:check`  | Fail (exit 1) if the committed catalog is stale — the freshness gate, aliased `gate:catalog` |
| `npm run catalog:report` | Print per-module metadata coverage.                                                          |

**Regenerating is not optional.** `gate:catalog` fails when the committed catalog does not match
`src/po/`, so a page-object change without `npm run catalog` is a red gate for whoever runs next.

For the `@aliases` / `@prerequisites` / `@observable-state` tags every public method must carry, see
[pom-metadata.md](pom-metadata.md).
