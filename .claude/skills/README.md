# Skills

Each skill in this folder is self-contained: `SKILL.md` plus its own `references/` and `scripts/`.
Read the skill itself — no summary of it is kept anywhere else. This file covers only how the skills
are **maintained**, which is not something a skill can document about itself.

## What skills do not own

A skill owns a **workflow**. It does not own the rules or the application:

- The numbered rules are in [`CLAUDE.md`](../../CLAUDE.md) and are cited by number, never restated.
- What the app under test looks like is in [`docs/app-under-test/`](../../docs/app-under-test/) —
  addresses, credentials, the Rails checkout, and the DOM facts that have already cost a run. Those
  lived under `gen-test/references/` until 2026-09-06, which meant an engineer writing a page object
  by hand had no path to them. They are shared now; link to them, do not copy them.

## Locally authored

`gen-test`, `verify-pipeline`, `architecture`, `write-web-test`, `write-api-test`, `pause-test` and
`correct-requirement` are written here and edited normally. They cite the numbered rules in [`CLAUDE.md`](../../CLAUDE.md) by
number rather than restating them, so a rule stays true in exactly one place.

## Vendor-managed: `playwright-cli` and `playwright-trace`

These two are **generated by the Playwright tools, not written here. Do not hand-edit them** — the
next refresh overwrites the edit without saying so. Regenerate after a Playwright upgrade:

| Skill              | Refresh with                         | Generated from                   |
| ------------------ | ------------------------------------ | -------------------------------- |
| `playwright-trace` | `npx playwright trace install-skill` | the repo's `@playwright/test`    |
| `playwright-cli`   | `playwright-cli install --skills`    | the **global** `@playwright/cli` |

`playwright-trace` documents `npx playwright trace`, a command Playwright itself now ships.

### The one casualty of every refresh

`playwright-cli/references/test-generation.md` is edited locally to say
`specs/product/<feature>.plan.md` where the vendor ships `specs/`. The refresh silently reverts all
four occurrences. Re-apply them, then confirm:

```powershell
grep -n "specs/" .claude/skills/playwright-cli/references/test-generation.md
```

This is the reason to check the diff after a refresh rather than committing it blind.
